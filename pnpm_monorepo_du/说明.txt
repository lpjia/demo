pnpm add -Dw husky
在提交或推送时，自动化的检查提交信息、检查代码 和 运行测试
连接git hooks
提交前验证, 不通过不让提交


初始化
pnpx husky init

多了个脚本命令, 不用管
"prepare": "husky"
安装单个包, 也触发prepare脚本, 没必要
改成 "postinstall": "husky", 也会触发
目前用 "first:i": "husky" 手动给项目装上 Git 提交校验


.husky\pre-commit文件, 写提交之前需要运行的命令

// pre-commit文件
#!/usr/bin/env sh
pnpm lint:prettier && pnpm lint:eslint && pnpm lint:spellcheck


-------------------------------------

pnpm add -Dw lint-staged
只对本次要提交的文件(暂存区文件)进行检查, 而不是整个代码库文件
lint-staged 通常与 husky 配合使用，从而在 Git 生命周期中实现自动化
安装后不会出现在devDependencies, 而出现在pnpm-lock.yaml文件里


配置文件
.lintstagedrc.js
里面有prettier、eslint、cspell检查命令并执行

脚本命令
"precommit": "lint-staged",


此命令脚本 "commit": "git-cz", 提交前会先自动运行 "precommit": "lint-staged",
所以命名precommit脚本, 钩子机制


-------------------------------------


当用pnpm commit提交时, 走标准化提交
流程: 
  lint-staged
  git-cz
    确认提交后才运行.husky\pre-commit的脚本命令
  prettier --write xxx 所有文件全prettier
  eslint
  cspell lint
  提交成功
当用git commit -m 'xxx'提交时, 
流程:
  运行.husky\pre-commit的脚本命令
    pnpm lint:prettier && pnpm lint:eslint && pnpm lint:spellcheck
  prettier --write xxx 所有文件全prettier
  eslint
  cspell lint
  提交成功



最终形成的方案如下
// pre-commit文件
#!/usr/bin/env sh
pnpm precommit

执行 pnpm commit 脚本命令会执行2遍 lint-staged, 问题不大(只检查暂存区文件)

改成"commit": "git-cz --dry-run", pnpm commit只执行1次 lint-staged, 底层不会执行git commit
还改成旧的 "commit": "git-cz",
