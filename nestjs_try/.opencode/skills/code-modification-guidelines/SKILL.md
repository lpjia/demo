# 代码修改规范

本项目对代码修改有严格的要求，每次修改代码时都必须遵守以下规则，**包括 opencode AI 助手在自动修改代码时同样必须遵守**：

## 规则一：保留已注释的代码

**绝对不要**修改或删除已经被注释掉的代码。这些被注释的代码有其存在的意义 —— 可能代表历史上下文、备选实现方案或计划中的改动。请将其视为只读内容。

- 如果一行以 `//` 开头，保持原样不动。
- 如果一个代码块被 `/* ... */` 包裹，保持原样不动。
- 除非用户明确指示，否则不要取消注释。

## 规则二：先注释旧代码，再新增代码

当需要改动已有的（未注释的）代码时：

1. **首先**，使用 `//`（行注释）或 `/* */`（块注释）将原有代码注释掉，保持其内容完全不变。
2. **然后**，在注释掉的代码旁边（正下方或适当的逻辑位置）添加你的新代码。

### 示例

如果原有代码是：

```typescript
const result = oldImplementation(config);
```

你应该改为：

```typescript
// const result = oldImplementation(config);
const result = newImplementation(config);
```

## 规则三：新增代码时说明修改原因

当在当前文件中新增代码时，在新增代码的顶部（函数、类或代码块的上方）添加注释，说明**为什么要这么修改**。

### 示例

```typescript
// 修改原因：原 login 方法未对密码进行加密校验，存在安全风险
const result = loginWithEncryption(username, password);
```

### 为什么这样做

- 保留了修改前的记录，方便追溯变更历史。
- 如果新代码出现问题，可以轻松回滚。
- 与项目保持历史上下文的惯例保持一致。
- 明确标注修改原因，方便后续维护者理解改动的背景和意图。

## 规则四：AI 助手必须遵守

**opencode AI 助手在执行任何代码修改操作时，必须严格遵循以上三条规则。** 这是硬性要求，AI 不得以任何理由绕过或违反。具体而言：

1. AI 在读取文件后，不得修改或删除任何已被注释的行或块。
2. AI 在改动已有代码时，必须先注释掉原始代码，再写入新代码。
3. AI 在新增代码时，必须在代码顶部添加注释说明修改原因。
4. AI 在执行修改前应主动加载本 skill，以确保规则被正确应用。
