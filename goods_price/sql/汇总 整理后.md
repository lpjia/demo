### price_history 表


* id  自增
* 商品id  product_id  // 关联到商品表的商品ID, 外键
* 单价  price // 商品价格（保留两位小数, 但是一般我常用一位）
* 计价单位id  unit_id // 关联到单位表的id, 外键
* 规格  spec // 5斤装, 4.5L, 36cm, 4个, 散称, 2大瓶
* 备注  note  // 比如说打5折, 比如说特价, 比如说618活动
* buy_time  // 价格生效的日期, 存日期+时间, 录入时用日期, 前端去处理
// 手动录入数据库的时间, 一般建议精确到分, 但是考虑到时间完整性, 用00:00:00
// 可能性有: 
> 1. 当天买的, 当天就录入信息, 那么buy_time有数据
> 2. 不是当天买的, 忘了当天录入, 隔了一段时间才录, 且知道购买时间buy_time
> 3. 不是当天买的, 忘了当天录入, 隔了一段时间才录, 不知道购买时间buy_time, 这该怎么搞? 置null


``` sql
-- 用varchar(10)来和无符号自增id来=, 没匹配上id后赋值'', 而不是某些默认值(比如0等)来干扰
`product_id` varchar(10) not null default '' comment '商品id',
```

### product 表


* id  自增
* 商品名  product_name  鸡蛋
* 别名  product_alias
* shop_id

> product表和price_history表是一对多的关系



### shop 表


* id  自增
* 商店名  shop_name // string, 长度20
* 别名  shop_alias
* 商店位置  position // string, 长度50
* 别名  position_alias
* 存活  is_alive
* sort_num // 排序


*商店名和位置或地址应该是绑定的
店和位置是一一对应的, 有可能是多对一, 暂时当作一一
位置可能会重复, 比如两个商店挨着是邻居
还有一种可能, 是原址重新开了家新商店, 比如金梧桐和金麦田*


### unit 表


* id  自增
* 计价单位  unit_name // 元/kg, 元/斤, 元/g, 元/瓶, 元/个, 元/包, 元/条, 元/组, 元/箱, 元/提
* sort_num // 排序

> 这个说白了是个map结构
