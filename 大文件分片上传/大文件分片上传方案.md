# 大文件分片上传方案

## 1. 整体架构

```
浏览器 (qian/)                 服务器 (hou/)
    │                              │
    │  ① 选择文件，计算文件 Hash    │
    │  ② 发起创建任务（文件名、Hash、总大小、总分片数）
    │ ──────────────────────────►  │ 创建上传任务，返回 taskId
    │                              │
    │  ③ 分片并发上传               │
    │    ┌─── chunk-1              │
    │    ├─── chunk-2  并发 3~5    │ 接收分片，写入临时目录
    │    ├─── chunk-3              │
    │    └─── ...                  │
    │ ──────────────────────────►  │
    │                              │
    │  ④ 所有分片上传完成           │
    │  发起合并请求                 │
    │ ──────────────────────────►  │ 合并文件，校验 Hash
    │                              │ 返回最终文件 URL
    │  ⑤ 秒传 / 断点续传检查       │
    │ ──────────────────────────►  │ 查询已上传的分片列表
```

---

## 2. 技术选型

| 层面 | 技术 | 理由 |
|------|------|------|
| 前端 | 原生 JS + ES Module | 项目现有骨架如此，无额外依赖 |
| 后端 | Node.js + Koa2 | 轻量、适合文件处理场景 |
| 文件 Hash | SparkMD5 (增量计算) | 浏览器端计算大文件 Hash，支持断点续传和秒传 |
| 临时存储 | 本地磁盘 `upload/tmp/taskId/` | 简单可靠，无需额外中间件 |
| 分片大小 | 5MB | 平衡 HTTP 开销和重试粒度 |

## 3. 前端设计 (qian/)

### 3.1 目录结构

```
qian/
├── index.html          # 入口页面（已有）
├── main.js             # ES Module 入口
├── uploader.js         # Uploader 核心类
├── hash.js             # 文件 Hash 计算（SparkMD5）
└── utils.js            # 工具函数
```

### 3.2 Uploader 核心类设计

```
class Uploader {
  file                // File 对象
  chunkSize = 5MB     // 分片大小
  concurrency = 3     // 并发数
  taskId              // 服务端返回的任务 ID

  // 状态
  chunks             // [{chunk, index, hash, loaded, size}]
  uploaded           // Set<已上传分片索引>
  status             // waiting | uploading | paused | done | error

  // 方法
  async createTask()        // 向服务端注册上传任务
  async uploadChunks()      // 调度并发上传
  async uploadChunk(i)      // 上传单个分片（含重试）
  async mergeRequest()      // 请求合并
  async checkStatus()       // 查询已有分片（断点续传）
  pause()                   // 暂停上传
  resume()                  // 恢复上传
  getProgress()             // 获取进度
}
```

### 3.3 关键流程

**① 文件选择 → 计算 Hash**
- 用户选文件后立即开始增量计算 SparkMD5
- 大文件（>100MB）计算 Hash 可能耗时数秒，使用 requestIdleCallback 或 Web Worker
- 显示 Hash 计算进度

**② 创建上传任务**
- 请求 `POST /api/upload/create`
- body: `{ filename, fileHash, totalSize, totalChunks, chunkSize }`
- 返回: `{ taskId, existed (秒传标识) }`
- 如果 `existed = true` → 直接返回文件 URL，完成

**③ 分片上传**
- 将文件按 5MB 切片，每片计算自己的 hash (md5)
- 并发控制: 同时最多 3 个分片上传
- 上传: `POST /api/upload/chunk`
- form-data: `{ taskId, chunkIndex, chunkHash, chunk }` (二进制)
- 失败自动重试 3 次，指数退避

**④ 合并**
- 所有分片上传成功后调用 `POST /api/upload/merge`
- body: `{ taskId, fileHash }`

**⑤ 断点续传**
- 进入页面后先检查 `localStorage` 中是否有未完成的任务
- 调用 `GET /api/upload/status?taskId=xxx`
- 获取已上传分片列表，只上传缺失的分片

## 4. 后端设计 (hou/)

### 4.1 目录结构

```
hou/
├── app.js              # Koa 入口
├── router.js           # 路由定义
├── upload/
│   ├── controller.js   # 控制器
│   └── service.js      # 业务逻辑
├── config.js           # 配置
└── package.json
```

### 4.2 API 接口

| 方法 | 路径 | 说明 | 请求体 / Query |
|------|------|------|----------------|
| POST | `/api/upload/create` | 创建上传任务 | `{ filename, fileHash, totalSize, totalChunks, chunkSize }` |
| POST | `/api/upload/chunk` | 上传分片 | form-data: `{ taskId, chunkIndex, chunkHash, chunk }` |
| GET | `/api/upload/status` | 查询已上传分片 | query: `taskId` |
| POST | `/api/upload/merge` | 合并分片 | `{ taskId, fileHash }` |
| GET | `/api/download/:filename` | 下载/访问文件 | — |

### 4.3 存储结构

```
upload/
├── tmp/
│   └── {taskId}/
│       ├── chunk-0
│       ├── chunk-1
│       └── ...
├── done/                  # 合并后的最终文件
│   └── {fileHash}/
│       └── filename.ext
└── db.json                # 任务元数据（简易数据库）
```

### 4.4 关键逻辑

**创建任务**
1. 检查 `done/{fileHash}` 是否存在 → 存在则直接返回秒传
2. 生成 `taskId` (uuid)
3. 创建 `tmp/{taskId}/` 目录
4. 保存任务元信息到 db.json

**接收分片**
1. 校验 `taskId` 是否存在
2. 校验 `chunkIndex` 是否在合法范围内
3. 将分片写入 `tmp/{taskId}/chunk-{index}`
4. 可选：校验分片 hash 是否匹配

**合并文件**
1. 校验是否所有分片都已上传
2. 按 index 顺序合并文件 (`fs.createWriteStream` + `pipe`)
3. 计算最终文件 hash 与前端比对
4. 将完整文件移动到 `done/{fileHash}/`
5. 清理 `tmp/{taskId}`
6. 更新 db.json

## 5. 边界情况处理

| 场景 | 处理方式 |
|------|---------|
| 网络中断 | 分片上传失败自动重试 3 次，指数退避 |
| 页面关闭/刷新 | 已上传的分片由服务端保留，重新进入页面后断点续传 |
| 同一文件重复上传 | 文件 Hash 相同 → 秒传（服务端已有完整文件） |
| 分片上传顺序乱 | 后端按 chunkIndex 排序后合并，不依赖上传顺序 |
| 并发冲突 | 每个分片独立写入，互不影响 |
| 同名不同文件 | 用 fileHash 区分，而非文件名 |
| 磁盘空间不足 | 合并时捕获写入错误，返回 507 |

2. **实现上传 API** — create / chunk / status / merge 四个接口
3. **前端 Hash 计算** — SparkMD5 增量计算，带进度
4. **前端 Uploader 核心** — 切片、并发、重试、进度
5. **前端 UI** — 文件选择、进度展示、分片状态
6. **断点续传** — 状态查询 + 本地持久化任务记录
7. **联调与边界测试** — 大文件、网络断开、重复上传
